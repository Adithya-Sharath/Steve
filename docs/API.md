# Steve Decode API

The public contract of Steve Decode: text or a voice note in, plain English (and optionally the same card in the worker's language) out. **Text only: nothing
in this API speaks or plays audio.** Generated by `scripts/make_api_docs.py` from the running app, so every JSON example below is real output (the machine
translation shape example is the exception, see section 4). The machine-readable contract is [`openapi.json`](../openapi.json) at the repo root; a small typed
TypeScript client is [`clients/ts/steve-client.ts`](../clients/ts/steve-client.ts).

**Stability:** response shapes are stable. A change to any field of `DecodeResponse`, `DecodedCard`, `TranslatedCard`, `DecodeExamples` or `DecodeHealthOut`
needs a decision record in `DECISIONS.md`, a regenerated `openapi.json` and this page (a test fails while they disagree). New optional fields may be added.

## 1. Basics

| | |
|---|---|
| Base URL | wherever the API runs, for example `http://localhost:8000` |
| Format | JSON (`application/json`), or `multipart/form-data` for a voice note |
| Identity | header `X-Worker-Key: wk_<24 to 128 URL-safe characters>` on `POST /decode` and `POST /decode/clarify`. Create one per device in the browser (`crypto.getRandomValues`, base64url) and keep it; the client library does this for you. It is a capability, not a password: only its SHA-256 is used and nothing about the worker is stored. |
| Public (no key) | `GET /decode/health`, `GET /decode/examples`, `POST /decode/inspect`, `GET /decode/eval`, `GET /health`, `GET /docs` |
| CORS | any origin listed in `CORS_ORIGINS` (comma-separated, or `*`) may call the API from a browser; `CORS_ALLOW_LOCALHOST=false` removes the built-in "any localhost port" rule. Headers `X-Worker-Key` and `Content-Type` are allowed; `Retry-After` is exposed. No cookies are used. |
| Works without keys | yes: typed text always returns an English card. Voice, translation and WhatsApp degrade gracefully (see `notes`). |
| Offsets | every `span` uses Unicode **code points** of the text it points into (`original_text`), not UTF-16 units: slice with `Array.from(text)` in JavaScript. |
| Wording | nothing here says "wrong" or "bad English", and no score is ever shown; `confidence` on the card is internal. |

## 2. Endpoints

### `POST /decode`

Decode a typed or pasted message, **or** a voice note.

**JSON body** `{ "text": string (1-2000 chars), "accent_hint"?: "ar"|"hi"|"ml"|"tl", "reply_language"?: "en"|"ml"|"hi"|"ur"|"tl"|"bn" }`

`accent_hint` says which sound patterns to expect from the speaker (Arabic, Hindi/Urdu, Malayalam, Filipino); leave it out when unknown. `reply_language`
asks for the card in that language as well (`en` or missing = English only).

```
curl -X POST http://localhost:8000/decode \
  -H "Content-Type: application/json" -H "X-Worker-Key: wk_demoDemoDemoDemoDemoDemoDemo1234" \
  -d '{"text": "yalla habibi come to the barking gate tree", "accent_hint": "ar"}'
```

Response `200` (`DecodeResponse`):

```json
{

    ],

  },

```

**Multipart body** (a voice note): fields `audio` (file: WAV recommended; also mp3, ogg, webm, m4a, flac), optional `accent_hint`, `reply_language`, and optional `text`
(used if the voice note cannot be decoded). At most **4 MB** (413) and, for WAV and Ogg where the length can be read, **30 seconds** (413).

```
curl -X POST http://localhost:8000/decode -H "X-Worker-Key: wk_demoDemoDemoDemoDemoDemoDemo1234" -F "audio=@note.wav" -F "accent_hint=ar" -F "reply_language=ml"
```

The audio goes to speech-to-text (Sarvam `saaras:v3`, mode `transcribe`, `en-IN`) and the transcript is decoded with the voice-note rules (a transcript is trusted
unless a critical word, a place, time, amount or number, fits its sentence badly). Audio is held in memory for that single call and dropped. `transcript` is
returned. If voice is not available (no key, daily limit, service down, nothing heard) you still get `200`, with `card: null` and a note to show the user, for example:

```json
{
  "card": null,
  "translation": null,
  "transcript": null,
  "decode_id": null,
  "notes": [
    "Voice isn't available right now, please type or paste the message."
  ],
  "say_back": []
}
```

### `POST /decode/clarify`

When the decoder is not sure it does **not guess**: `card.clarify` holds a question with options and the response carries a `decode_id`. Send the answer:

`{ "decode_id": string, "question_index": int, "choice": one of card.clarify[question_index].options, or "not_sure" }`

Response: the updated `DecodeResponse` (the same shape), with the answer applied and the actions recomputed. Example: a question, then the answer `parking`.

Open question (`POST /decode` with `'come to the barking or the building?'`, `accent_hint: "ar"`), abridged to the parts that matter:

```json
{
  "card": {
    "plain_english": "Come to the barking or the building?",
    "actions": {
      "where": null,
      "when": null,
      "what": {
        "value": "come",
        "evidence": {
          "start": 0,
          "end": 4,
          "text": "come"
        }
      },
      "how_much": null
    },
    "clarify": [
      {
        "span": {
          "start": 12,
          "end": 19,
          "text": "barking"
        },
        "options": [
          "parking",
          "barking"
        ],
        "question": "Parking or barking?",
        "slot": "where"
      }
    ]
  },
  "decode_id": "kR3x9Q0aV2mZ",
  "say_back": [
    "Sorry, parking or barking?",
    "Can you say that again slowly, please?",
    "Can you write it down for me, please?"
  ]
}
```

After `POST /decode/clarify` with `{"decode_id": "...", "question_index": 0, "choice": "parking"}` (abridged):

```json
{
  "card": {
    "plain_english": "Come to the parking or the building?",
    "actions": {
      "where": {
        "value": "parking",
        "evidence": {
          "start": 12,
          "end": 19,
          "text": "barking"
        }
      },
      "when": null,
      "what": {
        "value": "come",
        "evidence": {
          "start": 0,
          "end": 4,
          "text": "come"
        }
      },
      "how_much": null
    },
    "clarify": [],
    "changes": [
      {
        "heard": "barking",
        "meant": "parking",
        "reason": "Chosen from the question."
      }
    ]
  },
  "decode_id": null,
  "say_back": [
    "Can you say that again slowly, please?"
  ]
}
```

With `"choice": "not_sure"` the slot stays empty, the question moves to `card.skipped` and the response has a note and a `say_back` phrase to ask the other person (abridged):

```json
{
  "card": {
    "actions": {
      "where": null,
      "when": null,
      "what": {
        "value": "come",
        "evidence": {
          "start": 0,
          "end": 4,
          "text": "come"
        }
      },
      "how_much": null
    },
    "clarify": [],
    "skipped": [
      "Parking or barking?"
    ]
  },
  "decode_id": null,
  "notes": [
    "That's fine. You can show the other person the phrase below and ask again."
  ],
  "say_back": [
    "Sorry, parking or barking?",
    "Can you say that again slowly, please?",
    "Can you write it down for me, please?"
  ]
}
```

State: the original **text** (never audio) and the answers are kept **in memory only**, for `10 minutes` after the last answer, keyed by the worker key. The `decode_id` is
deleted when the last question is answered. An expired, unknown, finished or foreign id all answer `404`. Every answer returns the whole updated card.

## 3. The card (`DecodedCard`)

| Field | Meaning |
|---|---|
| `original_text` | the text that was decoded (the transcript for a voice note) |
| `plain_english` | the message in plain English: sound swaps applied, local phrases replaced, number words as digits |
| `actions.where / when / what / how_much` | `null` or `{value, evidence}`. `value` is a short lower-case phrase (`"parking gate 3"`, `"5 pm"`, `"don't come"`, `"50 dirhams"`); `evidence` is the `span` in `original_text`. A negation is always kept in `what`. A slot with an open question is `null`. |
| `changes[]` | words the decoder read differently: `{span, heard, meant, reason, confidence, source}` (`source`: `sound`, `phrase`, `context`). `reason` is a full sentence with the accent note when there is one. |
| `phrases[]` | local phrases explained: `{span, phrase, literal, social_meaning, category}` (yalla, khalas, inshallah, Maghrib, "kindly revert" ...). All meanings are draft text until a native speaker reviews them. |
| `clarify[]` | open questions: `{span, options[], question, slot}`. The decoder asks instead of guessing when two readings are close, and it never silently rewrites a negation, a number, an amount or a named time. |
| `skipped[]` | questions the worker answered with `not_sure` |
| `tips[]` | at most one short, neutral note on the sound pattern ("It often sounds like this: ...") |
| `confidence` | internal number 0 to 1; **never show it as a score** |
| `accent_used`, `path` | the hint that was used; `typed` or `voice` |

`DecodeResponse` = `{card, translation, transcript, decode_id, notes[], say_back[]}`. `notes` are human-readable fallbacks to show as they are. `say_back` are short, plain English
phrases the worker can **show** (as text) to the other person, such as "Sorry, parking or barking?". Steve never speaks them.

## 4. Translation (`translation`, optional)

When `reply_language` is `ml`, `hi`, `ur`, `tl` or `bn`, the settled English card is also returned in that language, **as text**. Only the decoded card is translated
(never `original_text`). Numbers, clock times, amounts and currency, the place phrase and the options of a question are protected: a deterministic check requires every
number in the English card to appear unchanged in the translation. **If the check fails, or no provider is available, `translation` is `null`, the English card is
still returned and `notes` says so. A translation that changed a number is never returned.** Not checked: that a negation survived the translation (the checker cannot
read those languages), which is why clients should keep the English card one tap away.

Shape (`TranslatedCard`; produced here with the offline fake provider, so the text is a marker, not real Malayalam):

```json
{
  "language": "ml",
  "provider": "fake",
  "verified_numbers": true,
  "plain_english": "(ml) Come to the parking gate 3 at 5",
  "where": "parking gate 3",
  "when": "5",
  "what": "(ml) come",
  "how_much": null,
  "phrases": [],
  "questions": [],
  "tip": null
}
```

`where` and `how_much` are never translated (place names as written on a sign; amount and currency). `provider` is `sarvam` (ml, hi, ur, bn) or `gemini` (tl, and the fallback).

## 5. Errors

Every non-2xx answer is `{"detail": "<sentence you can show>"}`.

| Status | When | Example body |
|---|---|---|
| `403` | missing or malformed `X-Worker-Key` | `{"detail": "Worker key required. Open Steve in the browser where you started."}` |
| `404` | `/decode/clarify`: expired (10 min without an answer), finished, unknown, or another worker's id | `{"detail": "That question has expired. Please decode the message again."}` |
| `413` | voice note over 4 MB, over 30 s (WAV, Ogg), or a request over 5 MB | `{"detail": "That voice note is too large. Please keep it under 30 seconds."}` |
| `422` | empty or over-long text, unknown `accent_hint` / `reply_language`, neither text nor audio, an unknown `choice` or `question_index` | `{"detail": "Send JSON like {\"text\": \"...\"} or a multipart form with an audio file."}` |
| `429` | rate limit; header `Retry-After: <seconds>` | `{"detail": "That was a lot of requests in a short time. Please wait 12 seconds and try again."}` |
| `500` | unexpected error (no internals are leaked) | `{"detail": "Something went wrong on our side. Please try again in a moment."}` |

## 6. Limits (environment variables; defaults)

`POST /decode`: 30 per minute and 500 per day per IP (`RL_DECODE_PER_MIN`, `RL_DECODE_PER_DAY`), 200 per day per worker key (`DECODE_PER_WORKER_DAY`).
Voice decodes also count against `STT_DAILY_CAP` (300 per day, all users); translation calls against `TRANSLATE_DAILY_CAP` (300). Audio: `DECODE_MAX_AUDIO_BYTES` (4 MB),
`DECODE_MAX_AUDIO_SECONDS` (30). Clarify state: `CLARIFY_TTL_SECONDS` (600). Every other route: 120 per minute per IP.

## 7. Privacy

Audio and message text are **never stored and never logged**. Audio lives in memory for one speech-to-text call. An open question keeps the original text in memory for 10
minutes (never on disk). Translations are cached in memory for 15 minutes by content hash. Nothing identifies a worker: only the hash of the device key is used, for limits.

```
python scripts/export_openapi.py          # regenerate openapi.json
cd api && uvicorn app.main:app --port 8000

```
